# Pod 1.0.0-rc3

A fix for 1.0.0-rc2, which could quit every minute or two while apps started from Pod's terminals were running. Nothing else changes from rc2.

From rc2, "Check for Updates…" installs it, and Pod's terminal sessions keep running through the update. From rc1, install it by hand from `Pod-1.0.0-rc3.dmg`: drag Pod into Applications and replace the old one while Pod is still open. The old Pod quits as for an update and leaves the terminal sessions running; open the new one and they are there. rc1's "Check for Updates…" can't install it, because rc2 changed the update key.

With Homebrew: `brew install --cask outof-place/tap/pod` for a new install. Installed from Homebrew at rc1, run `brew update && brew upgrade --cask --greedy pod` once; Pod can stay open, and quits as for an update when Homebrew replaces it. After that, "Check for Updates…" brings later releases, and a plain `brew upgrade` leaves Pod alone.

Pod needs macOS 27 or later on a Mac with Apple silicon.

## Fixed

- **Pod no longer quits on its own.** Pod watches the apps started from its terminals, to warn before one that would end the terminal sessions quits. It let go of an app while still watching it, and macOS's next notice about that app made Pod crash. Terminal sessions and agents survived each crash; the window did not.

## Known issues

- **Quitting an app that was started directly from a Pod terminal (for example by running its binary) can end all of Pod's terminal sessions about a minute later.** Start apps with `open -a <App>`, or from the Dock or Finder, instead. A fix lands before 1.0.
- **Relative links in the Markdown preview (for example `[x](docs/a.md)`) aren't clickable yet.** Only http, https and mailto links open.
